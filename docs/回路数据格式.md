# 回路数据格式与仿真引擎

代码在 `src/engine/`，纯 TypeScript，不依赖界面。入口：

```ts
import { loadCircuit, initialState, operate, step, run } from "src/engine";

const { circuit } = loadCircuit(jsonText);          // 自动升级旧格式 + 校验
let s = initialState(circuit);
s = operate(circuit, s, "SA_close", "closed");      // 操作接点，不推进时间
const { state, report } = step(circuit, s);         // 推进一个 tick
const result = run(circuit, s, { maxTicks: 200 });  // 运行到稳定 / 振荡 / 未收敛
```

## 文件格式（schemaVersion 1）

```json
{
  "schemaVersion": 1,
  "id": "breaker-control-basic",
  "title": "断路器控制回路（基本型）",
  "category": "控制回路",
  "reviewStatus": "草稿",
  "description": "……",
  "maxTicks": 200,
  "nodes": ["+KM", "-KM", "n1", "n2"],
  "components": [ … ],
  "layout": { "元件id": { "x": 120, "y": 40 } },
  "scenarios": [ { "title": "手动合闸", "steps": [ { "action": "operate", "target": "SA_close", "to": "closed", "explain": "……" }, { "action": "tick", "explain": "……" } ] } ]
}
```

### 元件类型

| type | 在回路上 | 字段 |
|---|---|---|
| `power` | 否 | `positive`、`negative`：正负电源节点名。不写这个元件时默认 `+KM` / `-KM` |
| `contact_no` / `contact_nc` | 是 | `between: [节点, 节点]`；`operable: true`（可点击操作）或 `controlledBy: 继电器或断路器 id`（二选一）；可操作接点可写 `initialState: "open" \| "closed"` |
| `coil` | 是 | `between`；`drives`：驱动的继电器或断路器；驱动断路器时 `action: "close" \| "trip"`；`coilKind: "voltage" \| "current"`；`impedance: "high" \| "low"`（默认 low）；`pickupDelayTicks` / `dropoutDelayTicks`（默认 0） |
| `relay` | 否 | `initialState: "picked" \| "dropped"`（默认 dropped）。由一个或多个线圈驱动，任一线圈有效即动作 |
| `breaker` | 否 | `initialState: "open" \| "closed"`；`operateDelayTicks`（默认 1） |
| `lamp` / `resistor` | 是 | `between`；`impedance`（默认 high） |
| `fault_injection` | 否 | `target`：目标元件；`kind`：`open_circuit`（断线，任何回路元件）/ `contact_stuck`（接点粘连）/ `coil_burnt`（线圈烧毁） |

**自保持**不单设元件：用“受继电器自身控制的常开接点，与启动接点并联”表达。

`controlledBy` 指向断路器的接点就是断路器辅助接点：常开在合位闭合，常闭在分位闭合。

### 格式迁移

改格式时把 `src/engine/types.ts` 里的 `CIRCUIT_SCHEMA_VERSION` 加 1，并在 `src/engine/migrations/index.ts` 登记升级函数。旧文件读入时自动升级。

目前登记了 0 → 1：早期草稿用 `from` / `to` 表示两端、用 `highImpedance: true/false` 表示阻抗。

## 仿真规则

### 一个 tick（同步更新）

1. 以本 tick 开始时的状态为准，找出正电源到负电源的所有导通路径；
2. 判定每个线圈是否动作（见下）；
3. 根据第 2 步的结果，**同时**计算所有线圈、继电器、断路器的下一状态；
4. 一次性写入。接点状态由继电器 / 断路器状态决定，所以接点在下一个 tick 才体现变位。

因此线圈带电到它的接点变位至少隔一个 tick；`pickupDelayTicks: n` 再多等 n 个 tick。

### 线圈动作判定（高低阻两档，沈 2026-10-31 同意）

1. 线圈必须在某条导通路径上；
2. 两端被一条全部由闭合接点组成的通路短接的元件不动作，也不算作路径上的高阻元件；
3. 有一条路径上除它以外没有其他高阻元件 → 动作；所有路径上都还有其他高阻元件 → 只有高阻线圈动作。

每个线圈的判定原因写在 tick 输出里，例如“HQ 未动作：路径上串有高阻元件 TWJ_coil，电流太小，低阻线圈不动作”。

### 终止条件

- **稳定**：一个 tick 后状态没有任何变化，且没有正在倒计时的延时；
- **振荡**：完整状态（含倒计时）与之前某个 tick 后的状态相同，报告循环的起止 tick；
- **未收敛**：超过 `maxTicks`（回路文件里的值优先，其次设置，默认 200）仍未稳定也未振荡。

### 实现时补充的简化约定（待沈确认）

AGENTS.md 没有写到下面几点，引擎先按这样实现，**需要沈确认或修改**：

1. **断路器同时收到合闸和跳闸命令时，跳闸优先**（tick 输出里会注明）。
2. **断路器一旦开始分合（倒计时中），命令消失也会完成动作**，不会中途停住。
3. **线圈的动作 / 返回延时在倒计时期间条件消失，倒计时取消**，下次重新计时（像时间继电器）。
4. **继电器有多个线圈时，任一线圈有效即动作**（例如防跳继电器的电流线圈启动、电压线圈自保持）。
5. 指示灯、电阻只参与“是否算高阻元件”的判断，不判断亮不亮（M2b 界面再按“是否在导通路径上且未被短接”显示）。
