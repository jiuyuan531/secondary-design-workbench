# 架构说明

## 技术选型

- Electron + React + TypeScript + Vite，主进程用 esbuild 打包。
- 数据库：**sql.js**（SQLite 编译成 WebAssembly）。

  AGENTS.md 推荐 better-sqlite3，并允许在原生模块打包困难时换成 sql.js。这里直接选 sql.js，原因是：
  better-sqlite3 是原生模块，需要针对每个 Electron 版本在 Windows 上重新编译，容易在别人的电脑上打包失败；
  sql.js 是纯 WebAssembly，不需要编译，在 Linux 上也能交叉打出 Windows 程序。
  代价是整个数据库放在内存里、每次写入后整体写回文件。本程序的数据量（项目、题目、笔记）很小，影响可以忽略。
  写回采用“先写临时文件再改名”的方式，避免写到一半断电损坏数据库。

## 目录

```
app/                     Electron 主进程（main.ts）和 preload
src/renderer/            React 界面
src/shared/api.ts        主进程与界面之间的接口类型
src/settings/schema.ts   所有设置项及中文说明（设置页按它自动渲染）
src/db/database.ts       数据库封装：打开、迁移、原子写回、设置读写、自检
src/db/migrations/       数据库表结构迁移（PRAGMA user_version 记录版本）
src/board/                项目看板：分类选项（enums.ts）、字段定义（model.ts）、增删改查与仪表盘（repo.ts）
src/db/backup.ts         备份文件校验
src/engine/              回路仿真引擎（M2a 开始）
data/seed/               内置草稿回路、故障规则、示例题（首次启动导入）
scripts/                 构建脚本
build.bat                Windows 一键打包
```

## 数据库迁移规则

- 迁移写在 `src/db/migrations/index.ts`，版本号从 1 开始连续递增。
- 已发布的迁移不再修改，改表结构一律新增迁移。
- 打开已有数据库时，如果有待执行的迁移，先把原文件备份为 `workbench.db.bak-v旧版本号-时间`，再逐个执行；
  任何一步失败都会回滚，数据库保持原样。
- 数据库版本比程序新（用新版程序打开过）时拒绝打开，避免旧程序写坏新格式的数据。

## 用户数据目录

Windows 下默认在 `%APPDATA%\二次设计工作台\`：

- `workbench.db`：数据库（位置可在设置里修改）
- `bootstrap.json`：数据库位置等必须在打开数据库之前就知道的设置
- `circuits\`：回路 JSON 文件（位置可在设置里修改）

## 无界面自检

```
ErciWorkbench.exe --smoke-test --user-data=<目录> --smoke-out=<结果文件>
```

打开数据库、写入并从磁盘读回一条记录，结果写成 JSON，成功退出码为 0。GitHub Actions 用它在去掉 Node.js 的环境里验证 exe。

## 项目看板（M1）

- 表单、列表都按 `src/board/model.ts` 的字段定义生成，字段中文名和填写说明只写在那里。
- 分类选项在 `src/board/enums.ts`：`value` 存进数据库，发布后不要改；`label` 是显示文字，可以随时改。
- 待确认问题的来源存在 `issue_sources` 表，一条问题可以有多个来源。勾选“来源之间有矛盾”时至少两个来源，并且每个都要写明说法；程序不要求选出哪一边对。
- 问题状态为“已确认”时必须填写确认人、确认日期、结论。
- 删除项目会连带删除它的卷册、任务、问题（删除前提示数量）；删除卷册时，挂在它下面的任务和问题保留，只是不再关联卷册。

## 备份与恢复

- 备份：把整个数据库文件写到用户选择的位置，写完后再读一遍校验。
- 恢复：先检查文件是不是本程序的数据库、版本是否兼容；替换前把当前数据库自动备份到 `用户数据目录\backups\恢复前自动备份-时间.db`；如果恢复的文件打不开，自动换回原来的数据库。
- 旧版本的备份可以直接恢复，恢复后会自动执行迁移升级到最新表结构。
